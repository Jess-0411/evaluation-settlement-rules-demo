本次修改规则（PRD）

积分到账时间与计算规则 · 2026-11-18

1. 背景与目标

将原积分规则拆分为到账时间与计算规则，支持逐笔到账、按评分周期结算、活动结束统一结算。管理员分别配置到账时机与得分算法，消除二者绑定造成的配置限制。

2. 用户与使用场景

学校评价管理员在新建活动的“评价设置”步骤配置手动评分积分。过程奖励使用立即到账；阶段性评价使用周期到账；活动终评使用活动结束到账。积分卡沿用原有累计方式和到账时间。

3. 需求范围

In Scope

两个单选下拉框、条件显示与必填校验、动态计算说明、本地保存回显、评分周期联动、需求说明抽屉。

Out of Scope

后端接口、真实评分计算、定时结算、实际积分流水、已发布活动配置变更、历史活动数据迁移及积分卡规则改造。本页保存与发布为本地原型反馈。

5. 核心流程与交互说明

  1. 默认立即到账，计算规则隐藏；每条有效手动评分逐笔累加。
  2. 选择周期到账或活动结束到账，显示无默认值的必填计算规则；选择后展示对应算法和示例。
  3. 周期到账：对当前周期内每位被评价人的各项记录分别计算并汇总，周期结束后到账，活动总分为各周期实际结算结果之和。
  4. 活动结束到账：对整个活动的各项记录分别计算并汇总，一次到账；不先拆分评分周期。
  5. 最高分取每项最高有效得分；累计得分累加全部有效得分；最后一次得分取每项最后一条有效记录。
  6. 平均分按每项有效评分总和÷有效评分记录数计算，再将各项相加；同一评价者多次有效评分分别计数，无评分不补零。中间过程不舍入，每次结算汇总后统一四舍五入至两位小数。
  7. 保存或发布时校验计算规则；通过后本地保存两个字段、评分周期及原评分结果权限，并显示原型成功反馈。
每次结算手动积分 = Σ（各评价项在本次结算范围内按所选规则计算的结果）
周期到账活动总分 = Σ（各周期实际结算手动积分）
积分卡另按原规则处理。

跨周期示例

同一评价项，第1天得分2、6，第2天得分4；评分周期为每天。

6. 异常场景与边界条件

  • 周期边界使用学校所在时区。活动首尾与自然周期取交集，活动结束结清最后一个不足周期；无评分周期不计分，缺失评价项不补零。
  • 评分周期为活动周期时，周期到账与活动结束到账的计算范围和到账时机一致。
  • 切回立即到账后计算规则不参与提交；再次切入延迟到账须重新选择。两种延迟到账方式互切保留当前选择。
  • 【假设】有效记录为未删除、未撤销且审核通过（无需审核时为已提交）的评分。最后一次按业务发生时间判定，同一时间取记录 ID 较大者；失效记录不参与计算。
  • 【假设】已结算记录变更、补评、活动重开及到账冲正由后续后端需求定义，本次原型不执行这些业务。
  • 本地存储不可用时显示“本地保存失败，请检查浏览器存储设置后重试”，不显示保存或发布成功。

7. 数据口径与埋点需求

计算分组为活动＋被评价人＋评价项＋结算范围。立即到账逐笔处理；周期到账使用当前周期；活动结束到账使用整个活动。平均分分母为有效评分记录数，各周期已舍入的实际结果再累加。

本地配置字段：timing（immediate / period / activity_end）、calculation（highest / average / sum / latest；立即到账为 null）、period（day / week / month / activity）。这些字段仅为本地原型状态，不代表已发布 API 契约。

【假设】后续接入埋点：settlement_timing_change（到账时间）、settlement_calculation_change（计算规则）、settlement_validation_failed（缺失字段）、settlement_settings_saved（配置及操作类型）。本次不发送网络请求，不采集人员信息。

8. 风险、依赖与限制

正式结算依赖学校时区、有效评分状态、评分时间、评价项标识与周期任务，结算任务须保证幂等。不同算法产生不同积分，平均分不得按全部评分合并计算或按评价者去重。当前仅交付配置交互与计算说明，成功提示不代表活动已发布至平台。

9. 验收标准

  1. 默认立即到账且不显示计算规则；延迟到账显示四种计算规则并标记必填。
  2. 延迟到账未选规则时，保存与发布均显示字段错误，不更新本地配置，不出现成功反馈。
  3. 延迟到账互切保留规则；切回立即到账清空规则及错误；再次切入不恢复旧值。
  4. 三种到账时间、八种延迟到账组合说明准确，评分周期切换时说明同步刷新。
  5. 同一项2→6→4的最高分、平均分、累计、最后一次分别为6、4、12、4；不同项分别计算后相加；跨周期示例符合第5节。
  6. 保存后刷新正确回显到账时间、规则和评分周期；立即到账配置中 calculation 为 null。
  7. 菜单无异常遮挡、键盘可操作；原有审核、次数、评分结果权限与需求抽屉交互正常。
